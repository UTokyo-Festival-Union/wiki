# 駒場祭委員会、五月祭常任委員会及び東京大学教養学部オリエンテーション委員会の共同プログラム開発に関する協定の実施に伴う駒場祭委員会及び五月祭常任委員会による共同プログラム開発に関する覚書

　（目的）
第１条　本覚書は駒場祭委員会、五月祭常任委員会及び東京大学教養学部オリエンテーション委員会の共同プログラム開発に関する協定（以下単に「協定」という。）第１４条の規定による委任に基づき、駒場祭委員会（以下「甲」という。）及び五月祭常任委員会（以下「乙」という。）両団体による共同プログラム開発等に関して、必要な事項を定め、甲の開発責任者（以下「丙」という。）及び乙の開発責任者（以下「丁」という。）の間で合意するところのものである。   
２　本覚書は、甲及び乙のみによる共同作成に限って適用する。

　（定義）  
第２条　本覚書における用語の定義は、協定及び第４条に掲げるサービスによる。

　（期）
第３条　共同プログラム開発に関する一期は、毎年１２月１日に始まり、翌年１１月３０日に終わるものとする。
２　共同作成にあたっては、その主たる活動時季を鑑み、その期によらず、甲が毎年６月１日から当該年の１１月３０日まで、乙が毎年１２月１日から翌年の５月３１日まで、それぞれ主導的立場を有するものとする。

　（管理）
第４条　甲及び乙で共同作成したプログラム等のうち、主要なものは協定第９条第２項に定める方法で管理する。ただし、管理に用いるサービス等の事項は、次の表に示す通りとする。
| サービスの種類 | サービスの名称 | サービスのウェブサイトのURL |
| ---- | ---- | ---- |
| バージョン管理システム | Git | https://git-scm.com/ |
| リポジトリ管理プラットフォーム | GitHub | https://github.com/ |
| タスク管理ツール及びドキュメントツール |	Notion | https://www.notion.com/ja |
| コミュニケーションツール | Slack | https://slack.com/intl/ja-jp/ |

|     |
| ---- |
| 備考　共同して管理するオーガニゼーション（URL「[https://github.com/UTokyo-Festival-Union](https://github.com/UTokyo-Festival-Union)」のウェブサイトで閲覧できるもの。以下この条及び第５条において単に「オーガニゼーション」という。）がプログラム等を含むリポジトリのオーナーシップを持つように設定する。 | 

２　協定第１０条に定める公開は、プログラム等を含むリポジトリの可視性をパブリックに設定することによって行う。
３　協定第１２条に定める移転は、プログラム等を含むリポジトリのオーナーシップをオーガニゼーションに移転し、又はオーガニゼーションがオーナーシップを持つリポジトリを作成することによって行う。
４　上記に定めるサービスがそのプラットフォーム内で提供するリソースに関して既知の制限があるときは、甲乙双方は当該リソースを濫用してはならない。また、甲乙それぞれの単独利用（自らの業務のみの用に供するものをいう。以下この項において同じ。）及び共同利用（単独利用でないものをいう。）に供する当該リソースの割合等の事項は、丙丁両者の協議による。
５　開発にあたるタスク、チケット及びイシュー等の事項の管理は、当時点において第３条に定める主導的立場を有する団体（以下この条及び次条において「代表団体」という。）が主導し、当該管理にあたっては、原則として代表団体のワークスペースを利用する。甲乙のうち、代表団体でない団体（次条において「非代表団体」という。）は、ワークスペースの該当するページについて、自らの開発従事者への編集権限付きの共有を求めることができる。

　（ブランチ等の運用）
第５条　共同作成は、各レポジトリの develop ブランチ（以下この条において単に「develop」という。）を中心として行い、その管理は代表団体が行う。
２　共同作成は、develop をブランチソースとしてブランチを作成し、その後作成を進めたのちにdevelop への Pull request（以下この条において「プルリク」という。）を発行することによって行う。当該プルリクは、原則として代表団体の開発従事者がレビューする。
３　協定第９条に定める保存は、レポジトリの main ブランチ（以下この条において単に「main」という。）において最新の状態として管理されるプログラム等の電磁的記録によって行う。代表団体は、develop における更新があるときは、develop から main へ、一月に一回を目安としてプルリクを発行する。非代表団体は、このプルリクを速やかにレビューするものとする。
４　大規模なシステムに関する共同作成においては、その複雑性等の特性を鑑み、甲及び乙は、前項のレビューに際して、その開発状況その他の事項について共有を行い意見交換する目的で協議を行うよう努める。
５　協定第９条にいう同意は、非代表団体の開発従事者が第３項のレビューを承認レビューとすることで行い、反対に、同意しない意思を示すことは、却下レビューを送信することによって行う。ただし、却下レビューは濫用してはならず、その送信の事由は原則として次の各号に示すもののいずれかに限る。
　一　合意した原則や、一般的なソフトウェア開発の基本設計原則への違反がある
　二　甲乙の一方、又は期に依存するプログラムを残置している
６　却下レビューを受け取ったときは、代表団体は速やかに修正を行うものとする。ただし、代表団体のみによる修正が困難である場合は、非代表団体もこれに協力するよう努める。
７　前項にもかかわらず、却下レビューに関する修正が困難であり、その修正が完了しないまま当該プルリクの発行の日から起算して１５日を超えた場合には、非代表団体は速やかに当該プルリクをマージする。
８　第３項の規定によるプルリクを経ない main へのプッシュ及びマージは、原則として認めない。
９　甲及び乙は、自らにおける運用の用にのみ供するブランチを作成することができる。

　（文書等の提供）
第６条　協定第８条に定める文書等の提供は、原則として丙及び丁の間での提供による。
２　甲及び乙は、附属プログラム（共同開発したプログラムではないが、共同開発したプログラムに不可分の依存性を持つものをいう。以下この条において同じ。）を互いに共有することができる。また、附属プログラムに関する文書等の提供については、協定第８条の規定を準用する。

　（単独開発プログラムの提供）
第７条　甲及び乙は、単独開発プログラム（一方の団体が他方の団体と共同せずに開発したプログラムであって、前条第２項の附属プログラムに該当しないものをいう。以下この条において同じ。）を、他方の団体に提供することができる。単独開発プログラムの提供は、丙及び丁の間での合意により行う。
２　単独開発プログラムに関する文書等の提供については、協定第８条の規定を準用する。
３　甲及び乙は、両団体の業務の類似性が高いことに鑑み、単独開発プログラムの提供が提供を受けた団体の業務に資するのに加え、当該プログラムの運用知見の共有又は開発成果の還元等を通じて、将来的に提供した側又は双方の利益に資するよう、相互の協力に努めるものとする。

　（開発の約束等）
第７条　甲及び乙による共同作成について、協定及びこの覚書に定めのない共同開発における約束その他必要な仔細の事項は、必要に応じてオーガニゼーションがオーナーシップを保有する wiki レポジトリの main ブランチにおいて最新の状態として管理される文書の電磁的記録（該当しない旨特筆のあるものを除く。第１０条において「ドキュメント」という。）によって、丙丁双方の責任のもと定めたものを記載しておく。
２　wiki レポジトリについては、第４条第２項及び第３項の規定は適用しない。

　（情報の秘匿）
第８条　甲及び乙は、協定第１０条、第１１条及び第１３条の趣旨を鑑み、協定の規定に基づいてのみ自らの委員等が知り得るところとなった事項（以下この条において「共同秘密事項」という。）について、自らにおける業務上の秘密情報とみなして扱う。特に、当該委員等と業務上の包括的な秘密保持契約を結んでいる場合は、その契約上秘匿義務の対象となる秘密情報に準ずるものとして扱う。
２　甲及び乙は、自らの委員等が一以上の共同秘密事項を前項のいうところにより知り得る状態におかれたとき（本項の規定が発効したときに当該状態におかれている場合を含む。）は、遅滞なく当該委員等と共同秘密事項の全部に関する永続の秘密保持契約（委員等たる資格を失ったあとも秘匿の義務を定めるものをいう。）を締結しなければならない。ただし、既に当該委員等と同様の効力を有する契約を締結している場合はこの限りでない。

　（公開）  
第９条　この覚書は、協定の目的を達成し、及びこの覚書の締結を証するために、甲乙双方の公示その他の適切な方法により公開しておく。

　（改廃）  
第１０条　この覚書の改廃は丙丁双方の合意による。改廃は、ドキュメント又は甲若しくは乙の公示において掲示する方法その他の適切な方法によって公開する。
